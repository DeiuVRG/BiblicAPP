# Translation pipeline (v3-lite): aligned translated editions

Status: specification for the first implementation (November 2026). Owner-facing summary and
rationale: `docs/skill-traducere-revizie.md` (review of the GP_AI_Translate skill) and
`docs/arhitectura-app-biblica.md` (section on the translation pipeline). Decisions are recorded in
`docs/decizii.md` (ADR-012).

## 1. Goal and principles

Turn a canonical source edition (`content/works/<slug>/edition-<src>.json`, produced by
`ingest-text`) into a canonical translated edition (`content/works/<slug>/edition-<lang>.json`)
that `build-pack` can sign and the app can show, with a human review sheet and provenance.

Principles (from the skill review, kept deliberately small):

1. **The source governs meaning.** Models translate; they never decide alignment or identity.
2. **One source paragraph → exactly one target paragraph**, same order, same section. Paragraph
   and section ids of the translation are generated by code (ULID) and stored once; every
   translated unit carries `sourceId`. Ids are never shared between editions.
3. **Independent critic.** The critic runs in a fresh context with the source, the draft and the
   rules only. It never sees the drafter's reasoning.
4. **Deterministic checks find anomalies; they do not decide exegesis.** Every check emits flags
   in one schema. A few typographic defects are auto-fixed (NFC, cedilla diacritics, whitespace);
   everything else is a flag for a human.
5. **Flags, not silent fixes.** A paragraph that cannot be rendered faithfully is delivered with a
   flag, never shortened, merged or split. Scripture quoted by the author is translated as the
   author's text and flagged `CITAT_BIBLIC`, so that a licensed Romanian Bible edition can replace
   it later; verse text is never produced from memory.
6. **Nothing is published without human review.** The merged edition is `draft` until a reviewer
   signs it off; the review sheet lists every open finding ordered by risk.

### 1.1 Target languages

Product rule (owner, 4 November 2026): every work is read in Romanian **and** in English. For an
English original (Vos 1903) the English edition is the source itself and only `ro` is produced.
For Latin, Greek, German, French, Spanish, Italian and Dutch originals the pipeline produces two
translations, `en` and `ro`, **each from the original** (never one from the other), both aligned
to the source paragraphs. A public-domain English translation, when one exists (NPNF, Loeb-era
editions before 1930), is given to the critic as a reference and is never copied.

Consequences for this specification: every material file is per target language
(`rules-<lang>.md`, `glossary-<lang>.csv`, `calques-<lang>.json`, `prompts/<lang>/…`); the
checks that depend on the target language (`CEDILLA`, `QUOTES_ENGLISH`, `QUOTES_UNBALANCED`,
`REF_FORMAT`, the Romanian book abbreviations) apply to `ro`, and `en` gets its equivalents
(straight-quote and curly-quote consistency, standard English abbreviations `Matt. 4:17`); the
`RESIDUE_*` check uses a function-word list of the **source** language (English for `en`
sources, Latin `et in ad non quod est sed enim autem cum ut qui quae`, German `und der die das
nicht ist dass auch wird sich`); the reference parser gets a Latin-notation grammar
(`Matth. IV, 17`, `Ioh. 3, 5`) before the first Latin work. **v3-lite implements the `ro`
target with English sources**; the generalisation is the first task before Augustine.

## 2. Data model

### 2.1 Schema additions (done, `packages/shared/src/schemas.ts`)

- `Edition.sourceEditionId?` – translations name the edition they are aligned to. `PackSchema`
  rejects a `kind: 'translation'` edition without it.
- `Section.sourceId?`, `Paragraph.sourceId?` – the unit of the source edition this unit renders.
  `PackSchema` rejects two paragraphs with the same `sourceId`.

The source edition is unchanged (no new fields), so the committed Vos pack keeps its bytes.

### 2.2 Directory layout

```
content/translation/                      shared materials, read by the agents (not by the app)
  rules-ro.md                             generic editorial rules for Romanian (EN/LA/DE/GRC → RO)
  output-contract.md                      the per-paragraph JSON contract, in prose
  glossary-ro.csv                         machine-readable glossary (see 2.4)
  calques-ro.json                         regexes for calques and false friends (see 2.4)
  profiles/<slug>.md                      per-work profile (tradition, register, names, exemplars)
  prompts/<lang>/{draft,critic,revise}.md prompt templates with {{PLACEHOLDERS}}, per target language
content/works/<slug>/
  edition-<src>.json                      canonical source edition (exists)
  edition-<lang>.json                     canonical translated edition (output of translation-merge)
  translation-<lang>/
    edition.json                          metadata of the translated edition (hand-written; ids
                                          generated once by translation-merge and written back)
    jobs/index.json, jobs/<jobId>.json    output of translation-jobs
    drafts/<jobId>.json                   written by the draft agent (TranslationOutput, pass 'draft')
    critic/<jobId>.json                   written by the critic agent (CriticReport)
    final/<jobId>.json                    written by the revise agent (TranslationOutput, pass 'revised')
    checks/<jobId>.json                   written by translation-check (CheckReport), one per checked file
    review.md                             reviewer sheet, generated by translation-merge
```

Everything under `translation-<lang>/` is committed: it is the provenance of the published text.

### 2.3 File schemas (zod, `packages/content-tools/src/translation/schemas.ts`)

`jobId` = `${slug}-${lang}-${NN}-${PP}` where `NN` = section ordinal + 1 (two digits) and `PP` =
part index within the section (two digits, from 00). Example: `vos-1903-kingdom-ro-01-00`.

```ts
TranslationJob = {
  jobId: string,                      // ^[a-z0-9-]+$
  workSlug: string,
  sourceEditionId: Id,
  sourceLanguage: string,             // e.g. 'en'
  targetLanguage: string,             // e.g. 'ro'
  section: { id: Id, ordinal: number, kind: 'chapter' | 'section', heading: string },
  part: number,                       // 0-based
  parts: number,                      // parts of this section
  paragraphs: Array<{
    id: Id, ordinal: number, kind: 'p' | 'heading' | 'quote' | 'note', text: string,
    references: Array<{ source: string, target: string, canonical: string[] }>,
  }>,
  context: {
    previousParagraph: string | null, // text of the paragraph before the first one of the job
    nextParagraph: string | null,     // text of the paragraph after the last one of the job
    previousSectionHeading: string | null,
  },
  wordCount: number,
  materials: {                        // repo-relative paths the agents must read
    rules: string, contract: string, glossary: string, calques: string, profile: string | null,
  },
}

Flag = {
  code: 'DE_VERIFICAT' | 'SURSA_POSIBIL_ERONATA' | 'TERMEN_NOU' | 'CITAT_BIBLIC' | 'AMBIGUITATE' | 'ALTA',
  severity: 'CRITIC' | 'MAJOR' | 'MINOR' | 'INFO',
  quoteSource?: string, quoteTarget?: string,   // exact quotes, never offsets
  note: string,
}

TranslationOutput = {
  jobId: string,
  pass: 'draft' | 'revised',
  model: string,                      // e.g. 'claude-sonnet-5-5'
  headingRo?: string,                 // required when part === 0 (translation-check enforces it)
  paragraphs: Array<{
    sourceId: Id,
    text: string,                     // min length 1, one paragraph, NFC
    flags?: Flag[],                   // default []
    scripture?: Array<{ ref: string, mode: 'reference' | 'quote-author-rendering' | 'allusion' }>,
  }>,
  notes?: string,
}

CriticReport = {
  jobId: string, pass: 'critic', model: string,
  findings: Array<{
    sourceId: Id,
    severity: 'CRITIC' | 'MAJOR' | 'MINOR' | 'SURSA_POSIBIL_ERONATA',
    category: 'omisiune' | 'adaos' | 'negatie' | 'modalitate' | 'agentivitate' | 'referinta' |
              'termen' | 'calc' | 'gramatica' | 'punctuatie' | 'alta',
    quoteSource: string, quoteTarget: string, problem: string, proposal: string,
  }>,
  verdict: 'ok' | 'revise',
  summary?: string,
}

CheckFinding = {
  check: string,                      // check code, see section 4
  severity: 'CRITIC' | 'MAJOR' | 'MINOR' | 'INFO',
  sourceId?: Id, message: string, quoteSource?: string, quoteTarget?: string, autofixed?: boolean,
}
CheckReport = {
  jobId: string, file: string, ok: boolean, strictOk: boolean,
  findings: CheckFinding[],
  stats: { paragraphs: number, sourceWords: number, targetWords: number, lengthRatio: number },
}

TranslationEditionMeta = {           // content/works/<slug>/translation-<lang>/edition.json
  edition: Edition with optional id   // kind 'translation', language, sourceEditionId, licence, provenance
}
```

All schemas are `z.strictObject` except where a default is given; unknown keys are an error
(agents must not invent fields).

### 2.4 Glossary and calques (machine-readable)

`content/translation/glossary-ro.csv`, header:
`term_id,source_pattern,target_pattern,tradition,scope,force,status,note`

- `source_pattern`, `target_pattern`: JavaScript regular expressions, matched case-insensitively
  with the `u` flag against a paragraph; `target_pattern` is matched against the translation.
- `tradition`: `all | protestant | orthodox | catholic | undivided`; `scope`: `all` or a work slug.
- `force`: `FIX` (the rendering is required when the source matches), `PREFER`, `WARN`,
  `FORBID` (the `target_pattern` must not appear when the source matches; with an empty
  `source_pattern` it must never appear).
- `status`: `APROBAT | PROPUS`. Checks apply both; the review sheet marks PROPUS rows.

`content/translation/calques-ro.json`: `Array<{ id, pattern, level: 'FORBID' | 'WARN', preferred, note? }>`,
`pattern` a regular expression over the translation (flags `iu`).

## 3. Commands (`packages/content-tools`, registered in `src/cli.ts`)

All commands resolve paths with `resolveUserPath`, print a one-screen `USAGE` on `--help` or
missing arguments, and never write outside the paths they are given.

### 3.1 `translation-jobs <edition-source.json> --lang <lang> [options]`

Splits the source edition into jobs.

- `--out <dir>` default `<work dir>/translation-<lang>`; writes `jobs/index.json` and
  `jobs/<jobId>.json`. Existing job files are overwritten (jobs are derived data).
- `--sections <list>` e.g. `1,2,5-7` (1-based chapter numbers = ordinal + 1); default all.
- `--target-words 900 --max-words 1500 --min-last-words 300`. Paragraphs are appended in order
  until the part reaches `target-words`; a paragraph is never split; a single paragraph longer than
  `max-words` forms a part on its own; a final part shorter than `min-last-words` is merged into
  the previous part when the sum stays ≤ `max-words + min-last-words`.
- Each paragraph gets `references` computed by the reference converter (section 5); `context`
  holds the neighbouring paragraphs' text and the previous section heading.
- `materials` paths: `content/translation/rules-ro.md`, `output-contract.md`, `glossary-ro.csv`,
  `calques-ro.json`, `profiles/<slug>.md` if that file exists, else `null`.
- `index.json`: `{ workSlug, sourceEditionId, targetLanguage, sourceSha256, jobs: [{ jobId, file,
  sectionOrdinal, part, parts, paragraphs, words }] }`. Deterministic for the same input.
- Prints one line per job: `jobId  paragraphs  words`.

### 3.2 `translation-check <output.json> --job <job.json> [options]`

Deterministic checks of a `TranslationOutput` (draft or final) against its job.

- `--fix` applies the safe auto-fixes (NFC, cedilla → comma-below, whitespace collapse/trim) and
  writes the file back (pretty JSON, 2 spaces, trailing newline). Fixed findings stay in the
  report with `autofixed: true`.
- `--glossary`, `--calques` override the materials named in the job.
- `--report <file>` default `<job dir>/../checks/<jobId>.json` (the `checks/` directory next to
  `jobs/`); always written.
- `--strict` makes MAJOR findings fail too.
- Exit codes: `0` when no CRITIC finding (and, with `--strict`, no MAJOR); `1` otherwise; `2` on
  usage or schema errors (the schema error message names the path, e.g. `paragraphs[3].text`).
- Prints a summary (`ok`/`FAIL`, counts per severity) and every finding on one line:
  `SEVERITY CHECK sourceId: message`.

### 3.3 `translation-merge --work <dir> --lang <lang> [options]`

Builds the canonical translated edition from the `final/` outputs.

- Reads `<work>/edition-<src>.json` (src from `translation-<lang>/edition.json`, which names
  `sourceEditionId`; the source edition file is found by matching `edition.id`), the meta file, all
  `final/*.json` (validated), all `critic/*.json` and `checks/*.json` if present.
- Coverage: every source paragraph must have exactly one final rendering. Missing paragraphs →
  exit 1 and a list, unless `--partial`, in which case only sections whose paragraphs are all
  covered are emitted and `edition.provenance.notes` gets the sentence
  `Partial translation: N of M sections.` appended (deterministic; no timestamps anywhere in the
  edition file, so that `build-pack` keeps its revision when nothing changed).
- Ids: sections and paragraphs reuse the ids of the existing `edition-<lang>.json` by `sourceId`;
  new units get `stableId()`; ids of units that disappeared are never reused. The edition id is
  generated once and written back into `translation-<lang>/edition.json` (like `ensureIds`).
- `work` is copied from the source edition. `sections` mirror the source sections (ordinal, kind,
  `parentId` mapped to the new ids, `sourceId`), `heading` = `headingRo` from the part-0 output of
  that section; if absent, the source heading is used and a WARNING is printed. `paragraphs`:
  `ordinal` and `kind` from the source, `text` NFC, `sourceId`.
- Refuses to merge an output that carries a `CRITIC` flag (or whose latest `checks/` report has a
  CRITIC finding) unless `--allow-critic`; the review sheet lists them either way.
- Writes `<work>/edition-<lang>.json` (pretty JSON like `ingest-text`) and
  `translation-<lang>/review.md`, then validates the result with `PackSchema`.
- `review.md`: a header (work, languages, coverage `N/M paragraphs`, `K/L sections`, models seen
  per pass, counts per severity), then one table ordered CRITIC, MAJOR, SURSA_POSIBIL_ERONATA,
  MINOR, INFO and, within a severity, by section ordinal and paragraph ordinal. Columns:
  `Severitate | Secțiune | Paragraf (sourceId) | Sursă | Traducere | Problemă | Propunere | Origine`
  where `Origine` ∈ `critic | draft | revised | check`. Critic findings with the same `sourceId`
  and `quoteTarget` as a flag in the final output are listed once (the final output wins). PROPUS
  glossary rows that matched are listed as INFO. The sheet is deterministic.
- Prints coverage, counts and the output paths.

`build-pack` is unchanged: `build-pack content/works/<slug>/edition-<lang>.json --out
apps/mobile/assets/packs/<slug>-<lang>` (pack id defaults to `<slug>-<lang>`).

## 4. Deterministic checks (`translation-check`)

| Check code          | Severity | Auto-fix | What                                                                                              |
| ------------------- | -------- | -------- | ------------------------------------------------------------------------------------------------- |
| `PARITY_MISSING`    | CRITIC   | no       | a job paragraph has no output                                                                     |
| `PARITY_EXTRA`      | CRITIC   | no       | an output `sourceId` is not in the job                                                            |
| `PARITY_DUPLICATE`  | CRITIC   | no       | a `sourceId` appears twice                                                                        |
| `EMPTY_TEXT`        | CRITIC   | no       | empty or whitespace-only text                                                                      |
| `SAME_AS_SOURCE`    | CRITIC   | no       | target equals source or Dice bigram similarity ≥ 0.9 (untranslated)                               |
| `GREEK_MISSING`     | CRITIC   | no       | a run of Greek script in the source (NFC) is absent from the target                                |
| `FLAG_CRITIC`       | CRITIC   | no       | the output itself carries a CRITIC flag (reported so that merge can refuse it)                     |
| `HEADING_MISSING`   | MAJOR    | no       | `part === 0` and no `headingRo`                                                                   |
| `RESIDUE_EN`        | MAJOR    | no       | English function words left in the target: ≥ 4 hits or ≥ 3 % of tokens from a fixed list          |
| `REF_MISSING`       | MAJOR    | no       | a canonical scripture reference of the source is missing from the target                          |
| `REF_EXTRA`         | MAJOR    | no       | the target has a scripture reference the source does not have                                     |
| `LENGTH_RATIO`      | MAJOR    | no       | target/source characters < 0.75 or > 1.6 (MINOR when < 0.85 or > 1.45)                            |
| `CALQUE`            | MAJOR    | no       | a `FORBID` calque or glossary `FORBID` rendering matched (`WARN` rows → MINOR)                     |
| `REF_FORMAT`        | MINOR    | no       | a reference in the target is not in Romanian notation (roman numerals, `Matt.`, `Jno.`, `vs.`)     |
| `NUMBER_MISSING`    | MINOR    | no       | an Arabic number of the source (outside references) is absent from the target                     |
| `GLOSSARY`          | MINOR    | no       | a `FIX` glossary row matched the source but its rendering is absent from the target               |
| `QUOTES_STRAIGHT`   | MINOR    | no       | straight `"` in the target                                                                        |
| `QUOTES_ENGLISH`    | MINOR    | no       | U+201C `“` in the target (Romanian opens with U+201E `„`)                                          |
| `QUOTES_UNBALANCED` | MINOR    | no       | count of `„` ≠ count of `”` (after discounting `“`)                                                |
| `CEDILLA`           | MINOR    | yes      | ş ţ Ş Ţ (cedilla) → ș ț Ș Ț (comma below)                                                          |
| `NFC`               | MINOR    | yes      | text not in NFC                                                                                   |
| `WHITESPACE`        | MINOR    | yes      | leading/trailing whitespace, runs of whitespace, line breaks inside a paragraph                   |
| `FLAG_PROPOSED`     | INFO     | no       | a PROPUS glossary row matched (listed for the reviewer)                                            |

English function-word list for `RESIDUE_EN` (lower-cased ASCII tokens): the, and, of, which,
that, with, this, is, not, from, by, his, their, been, were, into, than, those, these, there,
what, when, would, should, also, only, but, upon, into, through, between, because, however.
Tokens are `[A-Za-z]+` runs; words with Romanian diacritics never match.

## 5. Scripture references

Vos (and most 19th/early-20th-century English theology) cites `Book. chapter(roman). verses`:
`Matt. iv. 17; Mk. i. 15; Lk. iv. 43`, `Jno. iii. 3, 5; xviii. 36`, `Exodus xix. 4-6`,
`1 Cor. xv. 23-28`, `Matt. xiii. 24-30, 47-50`, `Lk. i. 17,35; xxiv. 19,49`,
`Matt. xviii. 23 ff.`, `Obad. 21` (single-chapter book), `cf. Mk. x. 17, with vs. 23`.

Grammar (source side): a run is `ref (';' ref)*`; a `ref` is `book chapter '.' verses`, or for
single-chapter books `book verses`, or a bare `chapter '.' verses` that inherits the book of the
previous ref in the run, or `vs. verses` / `ver. verses` that inherits book and chapter. `verses`
is a comma list of numbers or ranges (`-` or `–`), optionally followed by `ff.` or `f.`. Book
names: the usual English abbreviations and full names (`Matt`/`Matthew`/`Mt`, `Mk`/`Mark`,
`Lk`/`Luke`, `Jno`/`Jn`/`John`, `Is`/`Isa`/`Isaiah`, `Rev`/`Revelation`, `Ex`/`Exod`/`Exodus`,
`Ps`/`Psa`/`Psalm`/`Psalms`, …), with or without the period, optional `1 `/`2 `/`3 ` prefix. A
book word is only recognised when followed by a chapter and verses (so the English word `Is` at a
sentence start is not a reference).

Canonical form: `${BookCode} ${chapter}:${verseItem}` per comma item, with ranges kept as
`4-6`, `ff` kept as `23ff`, and single-chapter books rendered `${BookCode} ${verse}`. Book codes
are OSIS-like (`Gen Exod Lev Num Deut Josh Judg Ruth 1Sam 2Sam 1Kgs 2Kgs 1Chr 2Chr Ezra Neh Esth
Job Ps Prov Eccl Song Isa Jer Lam Ezek Dan Hos Joel Amos Obad Jonah Mic Nah Hab Zeph Hag Zech Mal
Matt Mark Luke John Acts Rom 1Cor 2Cor Gal Eph Phil Col 1Thess 2Thess 1Tim 2Tim Titus Phlm Heb
Jas 1Pet 2Pet 1John 2John 3John Jude Rev`).

Romanian rendering (status PROPUS until the owner approves the abbreviation list):
`Gen. Ex. Lev. Num. Deut. Ios. Jud. Rut 1 Sam. 2 Sam. 1 Împ. 2 Împ. 1 Cron. 2 Cron. Ezra Neem.
Est. Iov Ps. Prov. Ecl. Cânt. Is. Ier. Plâng. Ezec. Dan. Osea Ioel Amos Obad. Iona Mica Naum
Hab. Țef. Hag. Zah. Mal. Mat. Mc. Lc. In. Fapte Rom. 1 Cor. 2 Cor. Gal. Ef. Fil. Col. 1 Tes.
2 Tes. 1 Tim. 2 Tim. Tit Filim. Evr. Iac. 1 Pet. 2 Pet. 1 In. 2 In. 3 In. Iuda Apoc.`
Format: `Mat. 4:17; Mc. 1:15; Lc. 4:43`, `In. 3:3, 5; 18:36` (book not repeated inside a run,
like the source), ranges with en dash `1 Cor. 15:23–28`, `Mat. 18:23 ș.urm.`, `Obad. 21`,
`cf. Mc. 10:17, cu v. 23`. The target-side extractor recognises exactly this notation (plus
`v.`/`vv.` continuation and `;` chapter continuation) and maps it to the same canonical form;
the parity check compares the multisets of canonical items of source and target.

The converter lives in `packages/content-tools/src/translation/references.ts` and is pure.

## 6. Agent passes

Three passes per job, each a separate agent context (Sonnet, per project rule; effort `max` for
the pilot). Prompts are the templates in `content/translation/prompts/` with placeholders filled
by the orchestrator (`{{JOB_FILE}}`, `{{OUT_FILE}}`, `{{DRAFT_FILE}}`, `{{CRITIC_FILE}}`,
`{{FINAL_FILE}}`, `{{CHECK_COMMAND}}`).

1. **Draft** reads the materials named in the job, the job and nothing else; writes
   `drafts/<jobId>.json`; runs `translation-check --fix`; repairs parity/heading problems (only
   those) and re-runs until exit 0.
2. **Critic** reads rules, profile, glossary, the job (source) and the draft; never the drafter's
   notes beyond the flags; writes `critic/<jobId>.json`. It must quote exactly and propose a fix
   for every finding; it is told to prefer precision over volume and that an empty findings list
   with `verdict: 'ok'` is a legitimate result.
3. **Revise** reads the job, the draft, the critic report and the materials; applies the accepted
   findings (and says in a flag why a finding was not accepted when it disagrees, severity
   `MAJOR`); writes `final/<jobId>.json`; runs `translation-check --fix --strict`; iterates up to
   three times on CRITIC/parity problems; MAJOR findings it cannot resolve become flags.

The orchestrator (Workflow tool) runs `pipeline(jobs, draft, critic, revise)` and then
`translation-merge`. A later back-translation pass (Haiku) and embedding similarity are out of
scope for v3-lite.

## 7. Human review and publication

`translation-merge` produces `review.md`; the reviewer edits `final/<jobId>.json` (text or flags)
and re-runs `translation-check` and `translation-merge`. Reviewed state is recorded by the
reviewer in `translation-<lang>/edition.json` → `provenance.notes` for now (the admin app and
`content.paragraph_revisions.state` take over in M1). The pack is built only from a merged
edition; the app shows the translation as `Traducere` with the edition's licence note.

## 8. Tests and acceptance (for the implementer)

- Vitest in `packages/content-tools`: reference converter (the examples of section 5 plus the
  Romanian extractor and the parity comparison), chunking (never splits a paragraph, merges a small
  tail, respects `--sections`, deterministic ids and `index.json`), every check in section 4 with a
  positive and a negative case and the auto-fix path, `translation-merge` (id reuse across two
  runs, coverage failure, `--partial`, heading fallback, CRITIC refusal and `--allow-critic`,
  `review.md` ordering), CLI registration (`cli.test.ts` lists seven commands).
- `packages/shared` tests cover the new schema refinements (translation without
  `sourceEditionId` rejected; duplicate `sourceId` rejected; source edition unchanged).
- `pnpm -r typecheck && pnpm -r lint && pnpm -r test && pnpm format:check` pass; the committed
  Vos pack and `committed-content.test.ts` are untouched.
- No new runtime dependencies (a small CSV reader is written by hand; the format has no quoted
  commas except in `note`, which is the last column, so split on the first seven commas).
- Running the real pipeline on `content/works/vos-1903-kingdom/edition-en.json`:
  `translation-jobs … --lang ro` produces jobs with 131 paragraphs in total and every one of the
  176 reference runs of the source converted (print the count of unparsed reference-like
  fragments with `--verbose`; it must be 0 for Vos).
