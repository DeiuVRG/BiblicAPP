# @biblioteca/content-tools

CLI that turns source texts into signed content packs (see `docs/m0-spec.md` section 4 and
`docs/decizii.md`, ADR-007, ADR-010, ADR-011).

```bash
pnpm --filter @biblioteca/content-tools cli -- --help
```

Relative paths are resolved against the directory you ran `pnpm` from (`INIT_CWD`), so run the
commands from the repository root.

| Command       | Purpose                                                                         |
| ------------- | ------------------------------------------------------------------------------- |
| `ingest-text` | raw `pdftotext` output -> cleaned canonical edition JSON (`content/works/...`)  |
| `build-pack`  | canonical edition JSON -> `pack.json` + `manifest.json` (sha256 + Ed25519)      |
| `verify-pack` | byte-exact verification of a built pack against pinned public keys              |
| `keygen`      | generate an Ed25519 keypair (private key to `content/keys/`, gitignored)        |

Translation pipeline (specification: `docs/traducere-pipeline.md`):

| Command             | Purpose                                                                    |
| ------------------- | -------------------------------------------------------------------------- |
| `translation-jobs`  | source edition -> jobs: parts of a section, references, context, materials |
| `translation-check` | deterministic checks of a draft/final output against its job (exit 0/1/2)  |
| `translation-merge` | final outputs -> aligned translated edition + `review.md` (exit 0/1/2)     |

## Pipeline for a new work

```bash
# 1. Extract text. -layout keeps indentation (paragraph starts) and line-end hyphens.
pdftotext -layout book.pdf content/sources/<slug>/raw-layout.txt

# 2. Describe the work (work.json: metadata, ids may be omitted) and tune ingest.config.json.
#    Then clean it. Re-running keeps every existing id (output is byte-identical if nothing changed).
pnpm --filter @biblioteca/content-tools cli ingest-text content/sources/<slug>/raw-layout.txt \
  --work content/works/<slug>/work.json --verbose

# 3. Build and sign (dev key: content/keys/dev.key, never committed).
pnpm --filter @biblioteca/content-tools cli build-pack content/works/<slug>/edition-en.json \
  --out apps/mobile/assets/packs/<slug>-en

# 4. Verify (exit code 0 = valid) and list the pack in apps/mobile/src/content/bundled-packs.ts.
pnpm --filter @biblioteca/content-tools cli verify-pack apps/mobile/assets/packs/<slug>-en
```

The sample (Vos, 1903) was extracted with `pdftotext -layout` from
`incoming/part1/vos_1903_teaching_of_jesus_kingdom.pdf` (poppler 24.02).

## Translation pipeline

```bash
# 1. Split the source edition into jobs (writes <work>/translation-ro/jobs/). --verbose lists
#    every scripture reference conversion and the reference-like fragments that did not parse.
pnpm --filter @biblioteca/content-tools cli translation-jobs \
  content/works/<slug>/edition-en.json --lang ro --verbose

# 2. Agents write drafts/<jobId>.json, critic/<jobId>.json, final/<jobId>.json. After each write:
pnpm --filter @biblioteca/content-tools cli translation-check \
  content/works/<slug>/translation-ro/final/<jobId>.json \
  --job content/works/<slug>/translation-ro/jobs/<jobId>.json --fix --strict

# 3. Merge: edition-ro.json (ids reused by sourceId) and translation-ro/review.md.
pnpm --filter @biblioteca/content-tools cli translation-merge --work content/works/<slug> --lang ro
```

Each job carries the paragraph before its first and the one after its last paragraph as context,
also across a chapter boundary. Running `translation-jobs` again overwrites the job files and removes
the files of an earlier chunking of the same chapters that it no longer produces (jobs of chapters
outside `--sections` stay). `translation-merge --partial` refuses to drop a section that the
existing `edition-<lang>.json` already contains (its ids would be lost and a later merge would issue
new ones): restore its final outputs, or pass `--allow-shrink` to accept the loss.
`translation-check --fix` always writes the output back as pretty JSON.

`translation-ro/edition.json` is hand-written (licence, provenance, `sourceEditionId`); the edition
id is generated by the first merge and stored there. `content/translation/glossary-ro.csv` has
eight columns, no quoting: patterns must not contain commas (write `\x2C`); `\b`, `\B`, `\w` and
`\W` are Unicode-aware, so `\bbiserică\b` and `\bpoart\w* sensul\b` match across diacritics.
The `scope` of a row is `all` or a work slug: the Romanian file also serves English sources, so its
rows for Latin terms are scoped to the work whose profile lists them (`augustin-*`).
`content/translation/calques-ro.json` holds regexes over the translation. A bad pattern, a
missing materials file and a schema error all exit with 2.

Languages: `--lang` is the target language, `ro` or `en`; the source language is the language of the
edition (`edition-en.json`, `edition-la.json`, `edition-grc.json`). `translation-jobs
content/works/<slug>/edition-la.json --lang en` makes English jobs from a Latin edition: the
translated heading is `headingEn` (not `headingRo`), references are written `Matt. 4:17` (not
`Mat. 4:17`), the materials are `rules-en.md`, `glossary-en.csv`, `calques-en.json` and
`prompts/en/`, and `review.md` is in English. English and Latin sources have a grammar of scripture
references (Latin: `Matth. IV, 17`, `Ioh. 3, 5`, `ibid.`; the psalms keep the number of the Vulgate,
marked `vulgate`), and the residue check follows the source language (`RESIDUE_EN`, `RESIDUE_LA`,
`RESIDUE_GRC`); for a Greek source the Greek of the translation must be an exact copy
(`GREEK_COPY`: a whole run of the source, not a piece of a word). Scripture references are compared
(`REF_MISSING`, `REF_EXTRA`) for English and Latin sources only: a source without a grammar of
references (Greek, German) has none in its jobs. See `docs/traducere-pipeline.md`, sections 1.1, 4 and 5. The test data and where
they come from are in `src/translation/fixtures/` (first chapter of Augustine's *De spiritu et
littera*, the Creed of Constantinople).

## Keys

```bash
pnpm --filter @biblioteca/content-tools cli keygen --name dev --id dev-2026-11
```

`content/keys/dev.pub` is committed and pinned in `apps/mobile/src/content/trusted-keys.ts`
(a test keeps both in sync). CI signing: pass the private key JSON in an environment variable
(`build-pack --key-env SIGNING_KEY`); never commit it.

## How `ingest-text` cleans a text

All heuristics are data, in `ingest.config.json` next to the work:

- front matter before `firstChapterMarker` is dropped (`--keep-front-matter` keeps it), everything
  from `endMarker` on is dropped (printed indices);
- running heads are found by repetition with OCR-tolerant similarity and by the sequence of
  printed page numbers; page numbers and signature marks at the foot are removed;
- line-end hyphens are resolved from the text's own usage (compound seen inside a line -> keep);
- paragraphs start at an indented line, at an OCR mark that replaced the indent, or after a short
  line that ends a sentence (`length` mode for plain `pdftotext` output);
- chapter headings come from `chapters[]` (OCR text of headings is unreliable), drop caps and
  other one-off damage from `pageFixes[]`, recurring OCR damage from `replacements[]` and
  `wordFixes{}`; straight quotes become typographic quotes.

`--verbose` prints removed foot lines, indented lines that were not accepted as paragraph starts,
paragraph starts decided by the short-line cue only, and every hyphen decision, for review.

## Sources that are page-text directories, not PDFs

Some volumes of the owner's set (HathiTrust page text, `Anna's Archive` folders) are a directory of
`00000001.txt ...` files, one per page, with no PDF: there is nothing for `pdftotext` to extract.
The pattern, first used for Augustine's *De spiritu et littera* (`content/sources/augustine-de-spiritu-et-littera/`):

1. `extract.py` joins the page files, byte for byte, with a form feed between pages
   (`raw-layout.txt`; the page texts have no layout, so `raw.txt` is identical) and records the
   sha256 of every page file (`raw-pages.sha256`).
2. When the page carries the editor's apparatus that `ingest.config.json` cannot express (marginal
   references on the same lines as the text, footnotes of variant readings, English summaries,
   numbered sections), a deterministic `clean.py` (stdlib only, run `python3 -I`) cuts it out and
   writes `clean.txt` in the shape that `ingest-text` expects, plus `clean.log` with every removal.
   It fails (exit 1) unless its invariants hold (chapter and section sequences, no digits or
   reference leftovers, running heads matching the chapters).
3. `ingest-text clean.txt --work content/works/<slug>/work.json` does the rest: chapters, line-end
   hyphens, repairs of single words (`wordFixes`, `replacements`), stable ids. For numbered
   sections that start a paragraph, `clean.py` indents the first line by four spaces and the config
   uses `paragraphs.mode: "layout"` with `shortEndChars` set so high that the short-line cue never
   fires; running-head and foot detection are switched off (`minRepeats` 1000, `footers.zoneLines` 0)
   because `clean.py` has already removed them.

## Tests

`pnpm --filter @biblioteca/content-tools test` (Vitest): dehyphenation, paragraph joining,
running-head removal, heading detection, id stability, sign/verify round trip, tampering,
CLI end to end, checks on the committed sample pack, and the translation tooling (reference
converter checked against the whole Vos edition, chunking, every check, merge, review sheet; the
Latin grammar and the checks per pair of languages; dry runs of the three commands on Latin and Greek
fixtures).
